# 诺贝尔肖像馆

按用户本次要求交付手绘肖像、配套介绍网页或提示词。沿用用户的语言，默认中文。支持自动发现及 `$nobel-portrait` 显式调用。

## 先确定交付范围

- **肖像单图**：用户只要求“生成肖像”“转绘照片”“做头像”，只完成图像；需要照片，不需要奖项或个人资料，不自动创建网页。
- **肖像与网页**：用户提到“配套网站”“人物介绍网页”，完成转绘和单人物网页；需要照片及奖项，其他资料可创作补全。用户只要求为已有成图补网页时直接使用已有图，不重新生图。
- **提示词**：用户明确说“只要提示词”“提取画风”，只输出文字，不调用生图工具。没有人物照片时也可交付通用风格模板，清楚注明待替换的目标图变量。

用户指定画幅、背景、格式或只改某个环节时遵从其范围。未指定画幅用竖向 2:3；方图不要简单裁掉发顶或肩部，可在生图阶段调整构图。默认米白纸底不透明，用户要求透明时保留笔法并改变背景。

## 收集人物与奖项

- 生图必需一张清晰单人照片；仅制作网页时才需要希望获得的奖项。直接使用对话中已指定的信息，只询问当前模式所必需而缺失的内容，或多人照片中不明确的主体。请用户补照片时直接在聊天中提出。
- 可选：姓名、获奖年份、出生年月、出生地、工作单位、单位地址、获奖理由。不要逐项追问可选信息：缺失内容由你创作，姓名缺失时用“获奖者”或明确的创作别名，获奖年份缺失时用用户时区的当前年份。出生日期只到年月即可，不要无故编造具体日。
- 保留用户提供的字段，区分出生年月与获奖年份，区分单位名称与单位地址。编写奖项领域相符、具体但简洁的获奖理由，通常一句话即可；出生年月、履历和单位地址相互一致。虚构单位可采用虚构研究院，地址默认城市、国家，不必编门牌。
- 不从脸部推断姓名、国籍或出生信息。用户另行提供的画风图只控制笔触与配色，不充当这次要画的人，也不提供默认人物履历。
- 这是用户的创作获奖情景。网页用可见的一行说明“个人创作展示，非官方获奖记录”；自动编写的资料标注“创作设定”，并在 `profile.json` 的 `invented_fields` 中记录。用户明确要求制作真实人物档案时，不能用编造信息替代事实。

## 生成肖像

读取 [references/portrait-style.md](references/portrait-style.md)，按其中的文字规范转绘。本技能不附带画风图片；默认只需用户的人物照片，不要求额外提供风格图，也不自动寻找或下载参考素材。本地目标照片先用可用的图片查看工具（如 `view_image`）加载。

读取 [references/portrait-abstraction.md](references/portrait-abstraction.md) 理解从摄影细节到手绘形状的概括。核心是保持身份结构、减少描绘元素，并允许自然的手绘轮廓概括，不逐像素描摹。用户另行提供画风或成对示例时，可以查看并借鉴笔法，但要将其与目标人物身份分开；不把示范人物当作本次目标。

使用当前环境的图像生成/编辑工具做风格迁移，优先内置 `image_gen`，不需要另行索取 API key。若可用，按 `imagegen` 技能的工具流程执行；本技能的参考文档已提供核心提示词，无需依赖另一技能才能理解风格。

- 将人物照片标为 **identity / edit target**；仅在用户提供额外画风图时将其标为 **style only**。默认只传目标照片，画风由文字提示词确定。有本地路径时传入 `referenced_image_paths`；只有对话图片时使用最小必要的 `num_last_images_to_include`，两种引用方式不混用。若无法可靠传入目标照片，先取得缺失图片；可选风格图不可用时继续按文字规范，不用风格人物冒充目标人物。
- 保留眼距、鼻形、脸型、发际线、可见年龄、眼镜和表情；不擅自把人变老、加眼镜或替换服装。微笑时保留嘴形和牙齿纸白。衣服保留类别、领口和轮廓，省略非必要花纹；不让领带纹样抢过脸部。
- 提示词明确限定默认三色关系：纸白、黑墨、局部哑光金赭，包括唇部。面部以未着色纸白为主，额头中央、鼻梁和双颊中心留白；不要连续肤色渐变、毛孔、粉红嘴唇或水彩照片式晕染。头发用顺着发型的黑色刷痕与飞白，衣服内部大面积留白。用户要求保留某些原色时仅对指定元素放宽颜色约束。
- 黑墨负责五官和外轮廓，金赭负责有设计的短弧、窄带和少量不规则块面，纸白负责主要面部体积。头发合并为宽大的弧形发束，少数飞白露出纸底；不要以成百上千条发丝、小裂纹或散点模拟干刷。脸部的纸纹应与背景连续，而不是新增满脸色斑、疑似胡须和皮肤颗粒。眼睛可有小面积金赭虹膜与黑色瞳孔，但不发光、不放大眼形；用户要求保留原眼色时遵从。
- 未指定尺寸时目标 **1024 × 1536 px 或更高**，保留完整发顶和肩部，留适量纸底边距。此为提示词中的构图/清晰度目标，不是假定工具存在的 `size` 参数。根据实际输出记录宽高，不拉伸、不裁掉头发来强凑分辨率，不声称放大后增加了真实细节。
- 生成后按 [references/review-and-repair.md](references/review-and-repair.md) 查看结果：先身份，再笔触、留白、金赭色块，最后构图。发现偏差时做一次针对性修正，重复源照片身份约束，保留初稿和修正版以便选择。仍有差异时说明具体差异，不无限重试，不宣称与参考完全一致。
- 保存工具返回的真实图像到当前任务交付目录；不要只把网页链接指向工具缓存。内置工具不可用或失败时明确说明，保留网页模板、资料和提示词；不把输入照片、参考图或滤镜图片声称为新生成肖像，也不悄悄改走付费 API。

## 生成单人物网页

仅在本次请求包含网页时执行本节；肖像单图和提示词模式跳过。

读取 [references/page-and-data.md](references/page-and-data.md) 的布局、字段与构建说明。默认用本技能自带的 `assets/page-template.html` 和构建脚本完成网页，无需页面截图、外部账号或前端构建环境。

页面使用白色底色、金色标题、居中页眉、细分隔线、左侧目录和右侧人物资料。主体只介绍这一人：姓名、奖项与年份、肖像、出生年月与出生地、获奖时单位及地址、引号中的获奖理由。宽屏肖像在左、资料在右；窄屏纵向排列。所有导航应指向本页已有区域或真实下载文件，不创建无内容的采访、新闻或其他获奖者链接。

先完成 `profile.json`，再执行：

```text
python "<skill-dir>/scripts/build_page.py" --profile "<profile.json>" --portrait "<generated-portrait>" --out "<new-output-dir>"
```

`<skill-dir>` 指当前技能目录，以上路径占位需要替换为实际绝对路径。在 Codex 桌面可先调用 `load_workspace_dependencies` 查找运行时；没有配置时使用现有 Python。构建器转换 PNG/JPG 时需要 Pillow；它不负责 AI 生图、不推断人物资料。依赖不可用时先保留实际生成图和可用网页，再说明需要的格式转换条件。

网页模式默认交付可离线打开的 `index.html`、内嵌肖像的独立 `standalone.html`、`portrait.png`、`portrait.jpg`、`profile.json` 和生成用的 `portrait-prompt.txt`。肖像单图只交付图片与实际生成提示词；提示词模式只交付文字。转换保留实际像素，不额外缩放。用户指定输出路径或格式时遵从；已有非空输出目录用新版本目录，避免覆盖。

“配套网站”默认交付网页源文件及可打开的预览；请求公网发布时按当前可用托管流程执行，公开展示范围以用户授权为准。如用户指定 Sites 或现有框架，使用对应技能/工具，沿用本模板的内容与风格。不要为了生成一个页面自动发布用户照片。

## 验证与交付

检查文件、图片实际尺寸、字段与 `invented_fields` 一致、所有本页链接及资源路径。可用浏览器时预览桌面与窄屏，检查肖像加载、长姓名与长理由可换行、没有横向溢出；无法视觉预览时如实说明，只报告已完成的检查。

按本次模式交付：成图时展示肖像、给出图片链接和实际尺寸；请求网页时再提供网页链接并说明创作补全资料；仅提示词时不声称已生图。网页只是本地文件时不要称为已上线。若本次仅制作技能，明确样例页面只演示模板，不声称已完成照片转绘。
